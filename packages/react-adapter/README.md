# rendrix-react-adapter

Run [React](https://react.dev/) components on Rendrix's DOM. A `react-reconciler` host
config maps React's operations onto `document.createElement` / text / attribute patching —
there is **no `react-dom` and no second renderer**. The adapter is a thin, adapter-scoped
package over the real `react@19.3.1` + `react-reconciler@0.34.0` + `scheduler@0.28.0`
(declared in this package's own `package.json`; nothing else in the monorepo depends on
them).

```js
import { useState, render, h } from 'rendrix-react-adapter';

function Counter() {
  const [n, setN] = useState(0);
  return h('button', { onClick: () => setN(n + 1) }, `n=${n}`);
}
const unmount = render(h(Counter, null), document.getElementById('root'));
// ... later: unmount() removes everything and runs all cleanups.
```

## Props model with `h` (no compiler)

Without the JSX compiler there is one rule to remember: **props are plain values, compared
by identity on every render** — the exact opposite of the solid adapter, where a function
prop is a reactive accessor. Here a function prop is just a function:

```js
// static after first render: the child text only changes when the parent re-renders.
h('button', { onClick: () => setN(n + 1) }, `n=${n}`);
// dynamic attributes are plain values too — re-render to update them:
h('span', { className: on ? 'on' : 'off', style: { color: on ? 'red' : 'blue' } });
// conditional children are ternaries, lists are `array.map` (with `key`):
show ? h(Child, { n }) : h('i', null, 'hidden');
items.map(item => h('li', { key: item }, item));
```

`useState`/`useReducer`/`useMemo`/`useCallback`/`useRef`/`useContext`, `Suspense`/`lazy`,
`memo`/`forwardRef`, `createPortal`-free trees, and cleanup-returning effects all behave as
in the browser, because they run against the real DOM.

## Lifecycle

React has no `onMount`/`onCleanup` primitives; the adapter exports thin equivalents built
on effects (same semantics — mount-only setup, cleanup on unmount):

```js
import { onMount, onCleanup, useEffect, useLayoutEffect } from 'rendrix-react-adapter';

onMount(() => { const sub = subscribe(); return () => sub.unsubscribe(); });
onCleanup(() => console.log('unmounted'));
useLayoutEffect(() => { /* runs synchronously after DOM commit */ }, [dep]);
useEffect(() => { /* runs asynchronously via the scheduler */ return () => cleanup(dep); }, [dep]);
```

## Events

Event props (`onClick`, …) are attached with `addEventListener` **per element** (React's
root delegation is a `react-dom` concern and does not exist here). Three props are
normalized to the native event the element actually fires:

| prop | listens to |
| --- | --- |
| `onChange` on text-like `input` / `textarea` | `input` (per keystroke, React semantics) |
| `onChange` on checkbox / radio / file / `select` | `change` |
| `onFocus` / `onBlur` | `focusin` / `focusout` (these bubble; the handler still receives a `FocusEvent`) |
| anything else `onXxx` | the lowercased native event (`onClick` → `click`, `onDoubleClick` → `dblclick`) |

Non-function `onXxx` values are ignored (never set as attributes). Updates published from
inside a listener commit on the sync lane, so the DOM is current by the next task.

## What the vendor step does

`react`, `react-reconciler` and `scheduler` ship **CommonJS only**, and the Rendrix build
pipeline bundles ES modules (a bare `require` / `module.exports` has no host in the
runtime). `scripts/vendor.mjs` therefore generates ESM ports of the three pinned
`cjs/*.production.js` builds into `src/vendor/` (asserted: exact versions, no
`process.env`, no stray `require(`). The ports are git-ignored and regenerated by
`npm test` (via `pretest`), by the test run itself (`ensureVendor()`), and on demand:

```
node scripts/vendor.mjs
```

`src/shim.js` documents the (currently empty) set of globals React needs beyond the
prelude — today there are none: the scheduler falls back to `setTimeout(..., 0)` when
`MessageChannel` is absent, and everything else it touches exists.

## Divergences and limits

- **Sync mount, async effects.** `render`/`unmount` commit synchronously (legacy
  `ReactDOM.render` semantics via `updateContainerSync` + `flushSync`), and event-handler
  updates flush on a microtask. Passive effects (`useEffect`, `onMount`/`onCleanup`) flush
  asynchronously through the vendored scheduler — headless tests observe them after
  `wait`/`settle` steps. Programmatic updates outside events use the default (concurrent)
  lane; wrap them in the exported `flushSync` for deterministic commits (the fixture does
  this for its `setX` helpers).
- **Suspense timing.** Falling back and resolving work, including `hideInstance` /
  `unhideInstance` around Offscreen. React keeps a fresh fallback on screen for a short
  throttle window before committing fast-resolving content; the test's first `wait` covers
  it (~300 ms here).
- **Controlled inputs are semi-controlled.** `value`/`checked`/`selected` set the property
  and mirror the attribute, and `onChange` is normalized (table above), but React's
  value-restoration (clobbering user edits when the prop is unchanged) is not implemented.
- **No SSR / hydration.** `createContainer` is created fresh per `render`; hydration and
  `renderToString` entry points have no Rendrix host and are not exposed.
- **No TSX pragma.** `buildApp` pins `jsxImportSource` to `rendrix`, so `.tsx`/`.jsx` always
  targets the built-in direct-DOM runtime. Use `h` (or call `jsx` from
  `rendrix-react-adapter/jsx-runtime` directly) — see `src/jsx-runtime.js`.
- **No SVG namespace.** Elements are built with `document.createElement`; SVG tags become
  plain unknown elements. Real SVG rendering needs engine support and is out of scope.
- **React 19 rules apply.** String refs are removed (use callback refs / `useRef`); error
  boundaries, `useId`, transitions and `useSyncExternalStore` behave as in React 19.
  View Transitions and `Activity` have no host and are out of scope.
- **Pinned versions.** Verified against `react@19.3.1` + `react-reconciler@0.34.0` +
  `scheduler@0.28.0` (exact pins). Newer 19.x releases should work if they keep the same
  host surface; the vendor script fails loudly if the CJS shape it ports ever changes.
