TypeScript in.
Native pixels out.

If you can build it with TypeScript, you should be able to build it with Rendrix. Your TSX and CSS run in an embedded QuickJS engine, build a real DOM, get styled and laid out, and are drawn directly on the GPU with wgpu. No Chromium, no Electron, no WebView, no system browser.

Start building See the demo Install from npm 
bun install -g @renasine-studios/rendrix
rendrix init my-app
cd my-app && rendrix dev

Early alpha. Verified by hand on Windows 11 / NVIDIA RTX 3060 with Vulkan. macOS and Linux share the code and are built in CI, but have not been run by hand here.

What ships with your app.

A typical Electron app carries a browser and a Node.js runtime. A Rendrix app carries your compiled bundle and the Rendrix engine — DOM, CSS, layout, GPU and QuickJS — and nothing else.

These are layers, not file sizes. The measured artifacts are a bare Windows runtime of roughly 15–16 MB under the current release profile and, historically, a ~13.8 MB packaged app under an older profile; no like-for-like size, memory or startup comparison has been measured.

A normal web-style project: an index.html, a styles.css, and TSX that builds DOM nodes directly. Switch tabs to read each file, then use the simulation to see what it describes. 

<!doctype html>
<html>
  <head>
    <link rel="stylesheet" href="styles.css" />
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="src/main.tsx"></script>
  </body>
</html>
html, body { margin: 0; background: #000000; color: #ffffff; }
#root { display: flex; align-items: center; justify-content: center; height: 100vh; }
h1 { font-size: 48px; font-weight: 700; color: #ffffff; }
p { font-size: 16px; color: #a1a1aa; }
button { padding: 12px 20px; border-radius: 4px; font-size: 14px; font-weight: 700; background: #ffffff; color: #000000; cursor: pointer; }
import { render } from "rendrix/jsx-runtime";

let clicks = 0;
const label = (<p>No clicks yet.</p>) as HTMLParagraphElement;

render(
  <main>
    <h1>Hello, Rendrix</h1>
    {label}
    <button onClick={() => { label.textContent = `Clicked ${++clicks} times.`; }}>Click me</button>
  </main>,
  document.getElementById("root")!,
);

Three parts, one job each.

TypeScript/TSX and CSS are compiled to ES modules, a small QuickJS engine runs them against a real DOM with a real event loop, and Rendrix's own CSS, layout and GPU pipeline draws the result into the window. No browser engine is in the process.

TypeScript/TSX and CSS

A normal web-style project is type-checked and transpiled to ES modules. JSX from rendrix/jsx-runtime builds real DOM nodes directly — there is no virtual DOM and no compile-time markup subset.

QuickJS and a real DOM

The modules run in embedded QuickJS against a real DOM. Click, key and wheel input from a winit window drives capture and bubble events back into JS, so observers, forms and editing work the way you expect.

GPU drawing

Rendrix resolves the CSS cascade, lays out a box tree with flexbox, grid and block, builds a display list, and draws it directly to the window with wgpu.

From source files to one native executable.

Each stage writes a file you can inspect. The bundle is plain JSON, so you can open it and see exactly which modules the runtime will execute.

Your project

rendrix build

Type-checks and transpiles the project to ES modules, then bundles them as rendrix-app/1: a .rdxapp file that is plain JSON with modules and source maps.

{
  "format": "rendrix-app/1",
  "name": "my-app",
  "modules": {
    "main.js": "…"
  },
  "sourcemaps": { "main.js": "…" }
}

rendrix package

Appends the bundle to the runtime executable with a RENDRAPP trailer, producing one standalone file.

host bundle len RENDRAPP

Runtime executable, the .rdxapp JSON, an 8-byte little-endian length, then the RENDRAPP marker.

Writes dist/my-app.exe (bare Windows runtime roughly 15–16 MB under the current release profile).

A small, native backend.

The engine is a single process with capability checks, not a browser and not a sandbox for hostile code. These are the layers it is built from.

  1. DOM

    TSX builds a real DOM. Capture and bubble events come from OS input, with forms, editing, observers, Shadow DOM, custom elements, Range/Selection and contenteditable.

  2. CSS

    A real CSS engine resolves the cascade, specificity, inheritance and custom properties with var(), plus media queries, @supports, @layer, @container, nesting and animations.

  3. Box tree

    Styled nodes become a box tree laid out with flexbox, grid and block, along with flexible table, float and multicol approximations.

  4. Display list

    Layout output becomes a display list of SDF shapes, text, images and compositing layers — one draw call per shape, with a glyph atlas and offscreen compositing.

  5. wgpu

    The display list is drawn straight to the native window. QuickJS and layout are replaceable backends; when idle, the engine does no work.

Real DOM, real events

Click, key and wheel input from a winit window drives DOM capture/bubble events back into JS, with a real event loop.

CSS without a browser

Selectors including :has() and :focus-visible, container queries, nesting, gradients, shadows, filters, backdrop-filter and clip-path.

GPU-first drawing

One-draw-call SDF shapes, images (PNG/JPEG/GIF/WebP/SVG), Canvas 2D, SVG painting and experimental 3D scenes (RendrixScene).

Web APIs, native window

fetch/cookies, WebSocket, Workers, localStorage, crypto and clipboard, plus DPI-aware and multi-window support, OS file dialogs, drag-and-drop and an AccessKit accessibility bridge.

Replaceable backends

QuickJS and layout are swappable. The engine runs in one process and idles at zero work.

Capability checks, not a sandbox

App code runs with the user's privileges behind permissions.network, fs_read and fs_write, with a 5 s/task execution-budget interrupt on native. Not a security boundary.

Build the counter from a checkout.

Install the CLI with Bun or npm, author a web-style project, run rendrix dev, and package a standalone executable. No browser engine, Node runtime or Rust toolchain is needed to build an app.

Read the full docs, the CLI reference or the repository.

Install the CLI

bun install -g @renasine-studios/rendrix
rendrix --version

-g installs rendrix globally. Without it, Bun adds the package to the current project's node_modules. npm works too: npm install -g @renasine-studios/rendrix. View the package on npm.

Create and run a project

rendrix init my-app --template app
cd my-app
rendrix dev

rendrix dev builds and runs the app, then hot-reloads changed modules on the live DOM with script-cooperative state preservation. Add --no-hot to disable it.

Build and package

rendrix build
rendrix package
rendrix run

rendrix build type-checks and writes a .rdxapp bundle; rendrix package writes one standalone executable (bare Windows runtime roughly 15–16 MB under the current release profile), with optional --sign and --installer nsis; rendrix run launches it.

Render headlessly

rendrix render index.html -o out.png
rendrix render . -o frames/

rendrix render can also write a PDF or a frame sequence for a video pipeline. Use rendrix help for the full command list.

Inspect, test and integrate

rendrix check
rendrix doctor
rendrix help

Source maps, an --inspect JSON snapshot and headless scripted testing cover debugging. There is a Solid adapter, an experimental WebAssembly browser target (rendrix-web, which runs in a Web Worker) and mobile-input scaffolding in Session.

Status: an experimental prototype, stated plainly.

Rendrix is early alpha, not a production-ready GUI SDK. Verified by hand on Windows 11 / NVIDIA RTX 3060 with Vulkan only. macOS and Linux share the code and are built and tested in CI, but no manual hardware pass is recorded. A 2026-11-24 run passed 410 Rust tests, 44 CLI tests and 2 Solid adapter tests.

Works today

  • TypeScript/TSX and CSS in QuickJS, building a real DOM with a real event loop and capture/bubble events
  • Forms, text editing with undo and validation, pickers, observers, Shadow DOM, custom elements, Range/Selection and contenteditable
  • CSS cascade, specificity, inheritance, custom properties and var(), media queries, @supports, @layer, @container, nesting, keyframes and transitions
  • Flexbox, grid, block, flexible table, float and multicol approximations
  • GPU drawing with wgpu: one-draw-call SDF shapes, glyph atlas, compositing layers, images (PNG/JPEG/GIF/WebP/SVG), Canvas 2D and SVG painting
  • Experimental 3D scenes (RendrixScene, a small WebGL subset)
  • Web APIs: fetch/cookies, WebSocket, Workers, localStorage, URL, AbortController, crypto and clipboard
  • Native window: DPI, multi-window, OS file dialogs, drag-and-drop and an AccessKit accessibility bridge
  • Hot reload, source maps, --inspect snapshots, headless testing, a Solid adapter and an experimental rendrix-web target
  • rendrix init, dev, build, run, check, package, render and doctor
  • Benchmark (1,000 items / 9,009 nodes): idle, hover and scroll ≈1.2 ms/frame; DOM mutations ≈6.5–7 ms; resize ≈10 ms

Not yet

  • Full browser parity — Rendrix is not a browser and makes no browser-compatibility claim
  • A manual screen-reader pass (the AccessKit bridge exists, but Narrator/NVDA/VoiceOver/Orca have not been run)
  • macOS and Linux hardware validation — CI builds and tests them, but no manual pass is recorded
  • Browser verification of the WebGL2 fallback; browser-backed WebSocket, Worker and localStorage on the web target
  • Service Workers, XHR/IndexedDB, video/audio playback and canvas WebGPU
  • A working React adapter (an experimental one exists but its integration test fails), full table/float fidelity, writing-mode, WOFF2 and complex masks
  • A security sandbox for hostile code — capability checks and the 5 s/task interrupt are not a boundary
  • A quiet-machine cold-start measurement (a 2026-11-22 concurrent-load run reported an 81 ms first frame)

Only run code you trust: app code runs with your privileges behind small capability checks, and the execution-budget interrupt is not a sandbox. Early alpha, verified by hand on Windows 11 with Vulkan; macOS and Linux are CI-built but not manually validated. The bundle format is a prototype. No like-for-like size, memory or startup comparison has been measured beyond single-machine observations of the bare Windows runtime and a historical ~13.8 MB packaged app.
